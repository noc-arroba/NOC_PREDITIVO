Metodologia de Evidência

1

Duas fontes independentes: Monitoramento externo (servidor independente via HTTPS) e interno (roteadores MX204 via RR Flow API). Se ambas detectam o problema, a evidência é irrefutável.

2

Traceroute hop-a-hop de dentro do Arroba: Identifica exatamente em qual hop/AS está o gargalo de latência. Dados via API do RR Flow dos roteadores reais.

3

Thresholds baseados em impacto ao cliente: Latência >200ms = crítico, Jitter >50ms = crítico, Perda >3% = notável, TTFB >1000ms = páginas demoram.

4

Correlação multi-serviço: Quando múltiplos serviços degradam simultaneamente, indica problema de infraestrutura, não de serviço individual.

5

Tendência histórica: Comparação com medições anteriores detecta degradação gradual antes do cliente reclamar.
